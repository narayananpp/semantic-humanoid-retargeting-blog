## 2. Comparing agentic workflows for humanoid retargeting

::: anchor configurations

We compare **HuMoTAR** with [SPIDER](https://arxiv.org/abs/2511.09484)’s execution of the kinematic references generated by [HOI-Retarget](https://arxiv.org/abs/2609.34674). Using **[GPT-6 Astra](https://openai.com/index/gpt-6-astra/)**, we study iterative refinement with simulation feedback in three agentic configurations: *a single Codex agent, an independent agentic swarm and a collaborative agentic swarm*. We also evaluate *Astra one-shot* without tool calls or iterative refinement.

We compare these configurations under **a fixed time budget** and **an equal compute budget measured in agent-hours** to study the *compute–time tradeoff between agentic swarms and longer single-agent iterative refinement*.

- **Astra one-shot** generates motion and control code in one response, without tool calls or further revisions.
- **[Codex](https://github.com/openai/codex)** tests and revises its solution in a persistent coding session.
- **Independent agentic swarm** runs four Codex agents that develop their solutions independently.
- **Collaborative agentic swarm** runs four Codex agents that can share findings, request help and critique each other’s strategies.

For each task, the inputs to **HuMoTAR** are the human demonstration in SMPL format, an initial kinematic reference from HOI-Retarget, the task scene and the target object trajectory. The object trajectory is scaled for the robot and specifies the desired object motion. The agents write Python code to generate and refine *a reference motion for the whole body and hands*, which is the output of the framework.

The motion references and control code are executed in **[MuJoCo](https://mujoco.org/)** with **[SONIC](https://arxiv.org/abs/2511.07820) as the whole-body controller**. After each simulation, the agent inspects **images of the execution, object-tracking errors and contact measurements**. The available feedback is described in the [appendix](#simulation-feedback).
