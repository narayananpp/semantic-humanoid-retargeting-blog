HuMoTAR: Retargeting Through Visual Reasoning for Humanoid–Object Interaction

Narayanan Palghat Parameswaran1 Jay Karhade1 Haoyang He2 Neehar Peri3 Jay Patrikar2 Dong-Ki Kim2 Shayegan Omidshafiei2 Sebastian Scherer1,2 Deva Ramanan1
1Carnegie Mellon University 2FieldAI 3California Institute of Technology

Key Takeaways

  • How should one retarget human-object motions for humanoids? We posit that robotics is about enacting changes in the environment, and so retargeted motions should produce the same object trajectory.
  • Agentic models with a simulator in-the-loop produce dynamically feasible motions. We analyze the behaviour of our harness and find that iterating over targets with a verification reward that prioritizes object-trajectory matching is crucial.
  • Experience from related tasks improves refinement. Summaries of prior strategies and outcomes reduce object-tracking error on a new humanoid–object task from 23.35 to 7.77 cm under equal compute and time budgets.

1. Rethinking Humanoid Retargeting

Carry and place a chair

Lift, carry and place a clothes stand

Retargeting should preserve the task’s semantic intent. When a person carries and places a chair, what matters is what happens to the chair and where it ends up, not how the person holds it or how the body exactly moves. We therefore define the task semantically, and leave the robot’s contact strategy, posture and controller free to change (e.g., grasping the chair with two hands instead of one).

Kinematic retargeting prioritizes human motion. A humanoid differs from a human in proportions, joint limits and actuation, so each demonstration must first be adapted to its body. Most human-to-humanoid methods formulate this as a kinematic problem. For example, [1] fits the robot’s motion to human poses and object-relative contacts. This aims to reproduce the human reference motion, even when the robot’s body calls for a different strategy.

Kinematic feasibility does not guarantee physical execution. Sampling-based physics methods [3] address this by posing retargeting as a constrained optimization over the robot’s motor commands, sampling many candidate command sequences in a physics simulator and keeping those whose simulated motion stays closest to the reference (Figs. 1 and 2). However, errors in the input motion reference can lead them to the wrong contact strategy, and their open-loop execution is sensitive to the robot’s starting pose.

We introduce an agentic approach to retargeting built around two capabilities: reasoning about how to perform the interaction and querying the environment for evidence to guide refinement. The object reference motion defines the interaction goal. Specifically, the agent queries simulation feedback to decide how to revise the robot’s motion and control. For example, after a failed grasp, it requests a close-up of the hands and uses that image to adjust their placement.

2. Motion refinement with simulation feedback

We use GPT-6 Astra in the Codex coding environment, which provides tools and a persistent session. We refer to this configuration as Astra with Refinement. The walkthrough shows how Astra uses simulation feedback to refine a clothes-stand interaction. In this OMOMO task, the robot must lift the stand, carry it through a turn and place it on the floor. As shown in Fig. 3, Astra generates motion and control code from the human demonstration and an initial kinematic reference. It then tests this code in simulation and inspects execution images, object-tracking errors and contact measurements before the next revision.

3. Method Study

3.1 Retargeting approaches

Our goal is to produce dynamically feasible humanoid motions from human demonstrations. We compare three approaches to retargeting:

  • Classical retargeting. HOI-Retarget generates a kinematic reference, and SPIDER optimizes its execution in physics simulation.
  • Astra one-shot. GPT-6 Astra generates motion and control code in one response, without tool calls or iterative refinement.
  • Astra with Refinement. GPT-6 Astra tests and iteratively revises motion and control code through simulation feedback in the Codex coding environment.

Concretely, the agent receives the human demonstration in SMPL format, an initial kinematic reference from HOI-Retarget, the task scene and the target object trajectory (Fig. 3). The object trajectory specifies the desired object motion, scaled to the robot’s size. From these inputs, the agent writes Python code that generates and refines a reference motion for the whole body and hands.

SONIC provides whole-body control, and the agent may augment or replace its joint-angle outputs to complete the task. The Dex3 hands use impedance control. MuJoCo simulates each execution. After every trial, the agent inspects feedback (e.g., execution images, object-tracking errors and contact measurements) and revises its motion and control code.

3.2 Evaluation metrics

We evaluate all methods on 20 HUMOTO and 20 OMOMO tasks using object-tracking error and semantic success. Object tracking compares the simulated object trajectory with the target object trajectory. However, the robot may move at a different speed than the human, so we do not require the object to reach each position at the same time as in the demonstration. Instead, we compare corresponding stages of the object’s motion.

  • Mean ADD (cm): The average distance between corresponding points on the object at aligned poses, capturing both position and orientation error. Lower is better.
  • Position error (cm): The average distance between the simulated and target object positions. Lower is better.
  • Orientation error (°): The average angular difference between the simulated and target object orientations. Lower is better.
  • Semantic success: We use GPT-6 Astra as an LLM judge to compare videos of the human demonstration and robot execution. The judge determines whether the robot completes the intended interaction, even if its posture, grasp or timing differs. Each task receives a PASS or FAIL, and we report the percentage that pass. Higher is better.

We average object-tracking errors equally across tasks.

We first compare Astra with Refinement against our adaptation of HOI-Retarget + SPIDER to G1 with Dex3 on 20 HUMOTO and 20 OMOMO tasks. We give Astra with Refinement a budget of two hours per task and include Astra one-shot to measure performance without iterative refinement.

We find that Astra with Refinement achieves 75% semantic success, outperforming HOI-Retarget + SPIDER (17.5%) by 57.5 points and Astra one-shot (2.5%) by 72.5 points. Similarly, Astra with Refinement reduces mean object-tracking error to 12.63 cm, compared to 42.87 cm and 62.98 cm for HOI-Retarget + SPIDER and Astra one-shot (n = 39). Notably, Astra one-shot underperforms the optimization baseline on both metrics, highlighting the importance of iterative refinement with simulation feedback for successful physical execution.

4.1 Iterative refinement over time

Longer iterative refinement reduces best-so-far mean object-tracking error from 29.59 cm at 30 minutes to 10.21 cm at 120 minutes. Semantic success is also higher with a 120-minute budget: 75%, compared with 47.5% for the 30-minute budget.

5. Prior experience improves refinement on new tasks

We find that providing related experience, in the form of summaries of tested strategies, successes and failures, aids iterative refinement on a new task, reducing object-tracking error from 23.35 to 7.77 cm at equal compute and time. We illustrate this with a walkthrough of G1 righting a shelf from its side to an upright position. The prior experience comes from four other furniture interactions: carrying a table, lifting a chair, and pulling and pushing a chair.

We begin with a motion produced after 15 minutes of refinement without related experience. From this shared starting solution, we run two separate 15-minute continuations, one with related experience and one without. Since both continuations receive equal time and compute budgets, this comparison isolates the effect of experience on refinement.

6. Discussion

We conclude that retargeting should preserve the semantic intent of the interaction rather than require the robot to reproduce the human’s exact grasp, posture and sequence of movements. Our agentic approach achieves better object tracking and semantic success than classical retargeting [1], [3]. Closed-loop refinement also improves on open-loop, one-shot generation as the agent tests its proposed motion in simulation and uses the resulting feedback to revise it.

Hand morphology limits some interactions

In Fig. 7, G1 must lift and swirl a plate to reproduce the human’s interaction. Although it lifts the plate, it fails to complete the swirling motion. The agents adjust finger placement and try two-handed support, yet the grasp remains unstable during rotation. We posit that this difficulty can be attributed to the morphological gap between human hands and G1’s Dex3 hands: the fingers struggle to establish a stable grasp around the plate’s thin rim. Notably, none of the tested motion and controller revisions fully compensate for this mismatch.

7. Future Work

Although the refined reference motions could be used to train whole-body policies for deployment, our experiments combine SONIC with agent-written controllers and do not train task-specific policies. A natural next step is to evaluate whether RL fine-tuning on these references helps the robot handle disturbances and scene changes. We leave policy training and hardware deployment to future work.

Appendix

A1. Can a text description replace a motion reference?

Rather than providing a human motion reference or target object trajectory, we give Astra with Refinement a detailed task description, the scene and an initial robot–object state. The agent then refines an execution that follows the description, using SONIC for the legs and waist and custom arm and hand control. We show five examples below, each with its supplied command and resulting simulated motion.

Lift and inspect a basket

Text command

A basket rests on the floor in front of the person. Bend toward it and reach down with the right hand to take its handle. Lift the basket clear of the floor while straightening the body. Bring it in front of the torso, then use the other hand to help steady and turn it for inspection. Tilt and rotate the basket so its opening and different sides can be examined, rather than simply holding it motionless. Keep it under control throughout the lift and the changes in orientation. Finish standing with the basket held in front of the body; the demonstrated sequence ends while it is still being held.

Lift, lower and lift a side table

Text command

A small wooden side table with a raised curved rail stands on the floor in front of the person. Bend down, grasp the raised rail and lift the table off the floor as the body straightens. Keep the tabletop approximately level and the legs directed downward. Lower it back onto its legs in front of the body, then pause with the table supported on the floor. Bend toward it again and repeat the lifting action. Make the separate pickup, lowering, supported pause and renewed pickup recognizable, rather than replacing them with a single static hold or dragging the table along the floor. Remain near the table and keep each movement controlled.

Walk and turn while carrying a side table

Text command

Hold the small wooden side table with both hands in front of the torso, keeping its legs clear of the floor. Walk while carrying it along a curved path that turns the body through several facing directions, then comes back toward the starting area. The table travels with the person and turns with the body; its legs remain generally downward and the tabletop remains approximately level, with natural tilting during the turns. Keep both hands supporting the table while stepping and changing direction. Finish the walking sequence still holding the table in front of the body. The interaction should show sustained transport and turning, not stationary lifting or sliding on the floor.

Lift, move and set down a clothes stand

Text command

Stand beside a tall freestanding clothes stand with a circular base and branches near the top. Reach to its vertical pole around waist height with one hand. Lift its base clear of the floor, then take a few steps to move the stand to a nearby position while keeping the pole mostly upright. Move the body together with the stand rather than reaching from a fixed stance. Lower the circular base onto the floor, allow the stand to settle upright, and release the pole. Finish beside the independently standing object with the hand withdrawn. The lift, short transport and deliberate placement should be clearly visible.

Rock a wooden chair and return it upright

Text command

Face a wooden chair and bend toward it, placing both hands around the sides of the seat or nearby frame. Tilt and rock the chair so its seat and back lean and one pair of legs rises while the other pair remains near the floor. Guide the chair back toward an upright orientation and bring all four legs down under control. Keep the hands engaged while the chair changes orientation, and adjust the body with the movement. Finish with the chair upright and supported on its legs. This is a controlled rocking and righting interaction, not carrying the chair away or allowing it to fall.

A2. Can agentic swarms improve retargeting?

We investigate two four-agent configurations of Astra with Refinement, using GPT-6 Astra in the Codex environment. The independent swarm keeps each agent’s refinement separate. The collaborative swarm lets agents talk to each other during refinement.

Matched time: single-agent refinement versus swarms

We compare a single Astra agent with the independent and collaborative agentic swarms under the same 30-minute time budget. Each swarm runs four agents, so it uses four times the allocated agent-hours.

Agentic swarms improve retargeting within the same time budget, with the strongest task-completion results from inter-agent communication. Running four independent agents can help reduce “seed luck” and improve reliability, since one agent may find a solution that another misses. Here, the independent swarm improves object tracking and achieves semantic success on 21 tasks, compared with 19 for a single agent.

Inter-agent communication raises semantic success from 52.5% to 67.5% with the same four-agent budget. The agents divide experiments, test and improve each other’s controllers, and share unsuccessful results so other agents know what has already been tried. They also use feedback from other agents to correct mistakes in their evaluation. In a monitor task where the robot must lift and move a monitor, one agent identifies an object drop near the end of a rollout that another had judged successful. The second agent acknowledges the missed failure and identifies controlled placement as the next step.

Independent agents, on the other hand, sometimes spend part of their budget on overlapping approaches, without access to each other’s findings. In a tripod task where the robot must lift, move and place a tripod, two independent agents separately test unsuccessful two-handed grasps using closely overlapping strategies.

Matched compute: more refinement time versus more agents

In the previous section, we compared single-agent and swarm configurations under the same time budget. We now ask: at matched compute (agent-hours), is it better to give a single agent more time for reasoning and iterative refinement or distribute the budget across a collaborative swarm? For this study, we compare the collaborative swarm of four Astra agents running for 30 minutes each against Astra with Refinement running for 120 minutes. Both settings receive two agent-hours.

We make the observation that longer single-agent refinement outperforms the collaborative swarm in semantic success, achieving 75% versus 67.5%, at the cost of 4× the elapsed time.
